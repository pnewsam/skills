# Architecture document

Describe the current system from repository evidence, separating inference and proposed changes. Reuse an existing architecture document; otherwise use the destination requested by the user or the project's documentation convention. No registry-specific path is required.

Cover the system context, important runtime flows, source boundaries, state/data ownership, integrations, and material build/deployment constraints. Use a few diagrams only when they clarify relationships. Link implementation evidence for significant claims. Omit irrelevant sections and framework tutorials. Validate paths, names, diagrams, and the distinction between current behavior and intended design.
