# Review protocol

Return a verdict, a short reason, the validation run, and findings ordered by severity, in the shape defined in `references/review-output.md`. APPROVE needs sufficient evidence and no credible blocker; REQUEST_CHANGES needs a supported blocking defect; uncertainty is a question or COMMENT. Self-review uses COMMENT unless policy and explicit authorization permit self-approval. Report a reviewer model only from trusted runtime metadata, else `unknown`; a delegated reviewer reports its own model.

The agent owns the review-fix-validate-deliver loop. Take a second, context-isolated pass only when requested or when the change is high-consequence or contested. Task it with refuting the standing findings as well as surfacing missed ones, and drop any finding whose support cannot be re-grounded against the actual code. Prefer a fresh reviewer from a different model family when available and authorized, given intent, diff, context, and validation but not the prior verdict; disclose any fallback. Allow three repair rounds plus one clean review unless told otherwise; stop on convergence or the same finding surviving two repairs. Re-review after edits — an earlier clean review cannot certify later ones. A remote-readiness claim needs the remote head to match the reviewed candidate with required CI green. Do not post reviews, replies, or resolutions automatically; use authorized delivery.
