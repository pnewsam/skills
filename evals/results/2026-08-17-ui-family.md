## Verdict (per skill)

- **EVICT (13): `ui-content`, `ui-actions`, `ui-data-viz`, `ui-depth`, `ui-email`,
  `ui-feedback`, `ui-forms`, `ui-icons`, `ui-layouts`, `ui-onboarding`,
  `ui-responsive`, `ui-typography`, `visual-hierarchy`.** Bare model ties on every
  one of these cases; on `toast-banner-inline` the skill scored *below* bare. No
  durable, reproducible advantage.
- **`ui-patterns` → CONVERT / KEEP (lone survivor).** The only skill with a real,
  reproducible edge (3/3 vs 2/3 across reps): the bare model recommends the right
  container but consistently forgets to offer filtering/search for a large (40-row)
  collection; the skill includes it. Arm C (the ui-checker substitute note) did not
  recover it (0.778 < A−0.10), so a check doesn't substitute here. The durable value
  is a small scale-completeness objective ("at scale, offer filter / search /
  pagination; keep column alignment"), not the full prose — convert to that slim
  spec, or keep ui-patterns as the survivor index.

## Caveats

- Each skill rests on **one case** (the pre-registered contract, same as prior
  family A/Bs). The 10 clean ties are 3/3 reps at 1.000 on both arms — consistent,
  but a single case per skill. The openjudgment ties (`settings-layout-choice`,
  `toast-banner-inline`) are the softest.
- `visual-hierarchy` was earmarked in the plan for a separate decision; here it
  ties (evict signal), but flagging it explicitly.
- `toast-banner-inline`'s anchor ("transient post-submit failure = toast") is
  arguably contentious — both arms independently preferred an inline error. It
  penalizes both arms equally, so it does not change the evict read, but the case
  may deserve a rewrite.

Net if executed: −13 prose skills; keep/convert `ui-patterns`; `ui-color` /
`ui-spacing` checkers already kept; `ui-expert` slims to a survivor index.
