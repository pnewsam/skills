# Shape initiative

Apply `work-conventions`. Resolve the larger opportunity and choices before decomposing it. This is initiative-level discovery; ordinary uncertainty within one change belongs to `analyze-work`.

Read existing strategy, user evidence, constraints, and relevant product/code state. Treat a charter as evidence of intent, not immutable truth. Ask only for missing decisions that materially change direction; use supplied context without repeating an interview.

When the direction is open, compare a small set of materially distinct options. For each, state the intended outcome, supporting evidence, tradeoff, uncertainty, rough scope, and what would disprove the bet. Do not manufacture a fixed number of alternatives or turn speculation into market evidence.

For a charter request, use `references/charter.md` as a compact starting point. Preserve current decisions and update only what the evidence or user changed. Do not invent the user's vision or require a second approval to refresh an already requested document.

Return the recommended direction and consequential unresolved choices. Write a charter or options document only when requested or needed as an agreed durable initiative record. Continue to `plan-epic` when the user asked to plan the chosen initiative; one bounded outcome goes to `plan-work`. Stop at options for a discovery-only request. Do not implement or publish from this skill.
