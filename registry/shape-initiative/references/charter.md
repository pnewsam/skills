# Product charter

Capture the actual problem, intended audience, value proposition, chosen principles, explicit non-goals, and evidence of success. Include consequential uncertainty and what would cause reconsideration. A short existing document can already satisfy this need.

Ask for decisions the user has not supplied; never invent users, traction, metrics, or strategic commitments. Separate evidence from hypotheses. Refresh affected sections of an existing charter without restarting an interview or requiring an approval already given. Link material downstream implications; do not rewrite all plans automatically.
