# Browser coverage investigation

Map critical user journeys to existing tests and production evidence. Inspect runner configuration, fixtures, authentication, environment dependencies, selectors, skips, retry history, and duration before recommending additions. Distinguish absent coverage from flaky coverage and from infrastructure failures.

Prioritize by user consequence and exposure, not test count. Identify the smallest missing behavior or failing protocol and its proof. Do not invent a browser suite for a non-browser project. A coverage audit can report in chat; update an existing coverage initiative only when requested. Use one work unit for a coherent test change and a dependency-aware epic only for several independent outcomes.
